# M1 实现方案：墨邑古城·百花千灯会

> 里程碑：M1（工程骨架 + 城镇灰盒）
> 引擎：Godot 4.7.2 stable / GDScript / Forward+
> 设计来源：`MAP-01_墨邑花灯节地图设计_v0.1.md`、`CH01_序章第一章_剧情战斗装备开发稿_v0.2.md`

## A. 目标与完成标准

**目标**：从零建立可长期扩展的工程骨架，并把墨邑古城做成可跑、可读、可查案的灰盒场景。

**完成标准（对应设计文档 §10 首版制作顺序第 1—3 步）**

1. 第三人称角色可在城内自由探索，镜头可绕行、可被墙体阻挡。
2. 9 个区域（MY-T01 ~ MY-T09）全部落地，其中千灯桥、傩戏台、河埠三处为可辨识地标。
3. 10 名 NPC 按「初入城 / 得到线索后 / BOSS 战后 / 支线阶段」给出不同对白，不出现「所有 NPC 只有一条永久台词」。
4. 三条主线线索可任意顺序调查；收集状态实时影响任务日志与 NPC 台词。
5. 支线《河边第七盏灯》四阶段（问来历 → 捞灯罩 → 找灯牌 → 放灯）完整可完成。
6. 未集齐线索也能进入旧灯坊（兜底规则），不存在软锁。
7. 无头运行 0 脚本错误；数据与流程自检全部通过。

**不在 M1 范围**：战斗、存档、迷宫内部、BOSS、装备、正式美术、音效、四时段切换。

## D. 数据结构与关键规则

### D1 对白节点

```json
{
  "id": "MOYI_LIU_SQ_END",
  "npc": "NPC_LIU",
  "priority": 89,
  "required": ["SQ01_STARTED", "SQ01_READY_TO_LIGHT"],
  "forbidden": ["SQ_01_SEVENTH_LANTERN_COMPLETE"],
  "time_band": "any",
  "play_once": false,
  "lines": [{"speaker": "柳婶", "text": "……"}],
  "effects": {
    "set_flags": {"SQ_01_SEVENTH_LANTERN_COMPLETE": true},
    "add_item": {"id": "KEY_OLD_RIVER_LANTERN", "count": 1}
  }
}
```

**选择规则**（`DialogueRunner.select_node`）：
1. 取该 NPC 的全部节点 → 2. `required` 全满足且 `forbidden` 全不满足 → 3. 若 `play_once` 且已播则跳过 → 4. 取 `priority` 最大者。

优先级数值约定：90+ 关键主线/过场，80+ BOSS 战后，60—70 支线专属与阶段推进，50—55 线索反馈，20—30 生活对白，≤10 默认闲聊。

**效果支持**：`set_flags` / `clear_flags` / `add_clue` / `add_item{id,count}` / `start_quest` / `add_party`。

### D2 任务阶段：旗标驱动、实时重算

阶段不按顺序硬编码推进，而是「**第一个 `complete_on_flags` 未被全部满足的阶段就是当前阶段**」：

```json
{"id": "CH01_030_GATHER_CLUES", "objective": "调查三条线索……", "complete_on_flags": ["ALL_CLUES"]}
```

好处：读档、跳阶段、兜底路径都不会错位；任务日志永远反映真实状态。
派生旗标 `ANY_CLUE`（≥1 条线索）、`ALL_CLUES`（=线索总数）由 `GameState` 自动维护，供对白条件复用。

### D3 地图 JSON → 几何体

`TownBuilder` 支持的结构类型：`terrain / water / wall / gate / street / plaza / bridge / building / stage / stall / lantern_row / tree / bamboo / well / sign / boat / crate / barrel / desk / ramp`，加 `npcs / interactables / triggers / spawn` 四个装配段。

- 灯笼串带**光照预算**（`LIGHT_BUDGET_MAX = 30`）：超出预算的灯笼只发光、不挂 OmniLight，避免灰盒阶段就爆光照。
- 建筑自动生成：石基、四面墙（正面留门洞 + 门楣）、悬山顶、木梁、**暖灯窗**、招牌（含 3D 文字与门前补光）。
- 戏台自动生成：台面、四柱、顶棚、后台幕布、匾额、正面坡道。

### D4 交互与门的规则

- 交互判定用「组 `interactable` + 距离 ≤ 3.4 米」，不走物理层，避免层配置出错。
- 门的开启条件：`MSQ_OLD_LANTERN_WORKSHOP_OPEN`（罗班主确认）**或** `ALL_CLUES`（兜底，保证不漏线索也能进迷宫）。
- 触发器过场需要 `COMP_JIANGATANG_JOINED + ANY_CLUE`，且 `play_once` 过场只播一次。

自检覆盖：数据完整性（对白/NPC/物品/任务/线索交叉引用）、对白优先级 6 例、任务阶段推进 8 例、暗门兜底、支线全流程、地图结构（交互点对白存在、建筑范围不重叠）。

**本轮自检抓出的真实缺陷（已修）**

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | `GameData` 加载即崩 | `_validate()` 调用了不存在的方法名 `_dialogue_nodes_for()` | 改为 `dialogue_nodes_for()` |
| 2 | 取得线索后 NPC 台词不变化 | `add_clue()` 只写 `clues`，没写 `flags`，而对白条件读的是 `flags` | `add_clue()` 同时置旗标（线索即证据标记） |
| 3 | 校验器误报物品不存在 | `add_item` 是 `{id,count}` 字典，校验器却拿它的键当物品 ID | 取 `add_item.id` 校验 |
| 4 | 城镇生成中断 | ① 对材质调 `darkened()`（该方法属于 Color）② `for s in [-1.0,1.0]` 元素为 Variant 导致类型推断失败 ③ 编辑事故把两行并成一行 | 用颜色做暗化、循环变量显式标类型、拆行 |

## G. 未实现内容与下一步

**M1 明确未做**
- 战斗（行动条、技能、敌人 AI、BOSS）
- 存档 / 读档（当前进度只存在内存，关掉即归零）
- 旧灯坊迷宫内部（暗门只到「推门看到向下的石阶」）
- 装备、锻造、材料经济
- 正式美术、动画、音效、四时段切换（`time_band` 字段已预留）
- NPC 走位与日程（NPC 固定站位；阿禾「追进侧巷」目前由触发过场叙述，人不会真的跑掉）

**下一步最佳选择：M2 旧灯坊迷宫 + 存档系统**
理由：① 存档是当前最硬的风险（P0），越早做越省事；② 迷宫是 M3 战斗的载体，先有空间再有战斗；③ M1 已把「状态 = 数据」的边界划清，存档只需序列化 `GameState` 的 6 个字典 + 任务阶段缓存。

**建议的 M2 任务拆分**
1. `SaveManager` 单例 + `user://save_01.json` + `SaveVersion` 字段；存档内容 = 旗标/线索/物品/队伍/已播对白/时段/玩家位置。
2. 主菜单与「继续游戏」入口（读档后把玩家放回保存位置）。
3. `map_workshop.json`：MY-D01 封灯门 / MY-D02 纸轿廊 / MY-D03 借面戏台 / MY-H01 隐藏戏箱 / MY-D04 倒悬灯街五个空间，复用 `TownBuilder` 的同一套结构类型（新增 `corridor / door_puzzle / hidden_room`）。
4. 回到墨邑后的状态变化（灯桥恢复、核心 NPC 新对白、`MSQ_MOYI_AFTERSTATE`）。
