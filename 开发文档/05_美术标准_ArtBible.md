# 美术标准（Art Bible）v1.0

> 适用范围：《云阙行：九灯照夜》全部可进入场景。
> 目标：个人开发者 + 近似零预算条件下，做出**风格统一、比例可信、材质可辨**的东方仙侠世界。
> 配套文档：`06_墨邑古城_美术实施方案.md`（首个美术任务，按 A—H 格式）。

## 0. 三条不可违背的前提

| 前提 | 含义 | 反面案例（禁止） |
|---|---|---|
| **概念图 ≠ 游戏资产** | AI 概念图只用于确定构图、色彩与气氛，不能导入 Godot | 「我出了概念图所以场景做好了」 |
| **灰盒 ≠ 成品** | 当前 `yunque/` 里的城镇是**带光照氛围的灰盒**：胶囊 NPC、盒子建筑①，只用于验证路线、视线、时长与交互 | 用灰盒截图对外当宣传图 |
| **风格统一 > 单张漂亮** | 任意两张场景图并排，材质、色彩、光照方向必须像同一个世界 | 每进入一个新区域就换一套色调与材质习惯 |

① 灰盒现状见 `yunque/shots/moyi_*.png`；正式资产替换计划见 `06_…` 与 §9。

## 1. 风格定义

**一句话**：适度写实的中国木构世界 + 绘画感的柔和光照 —— 让人相信这是一个真实存在、有人居住的古代城镇。

| 维度 | 标准 | 禁止 |
|---|---|---|
| 造型 | 结构合理、比例可信；木构有榫卯、斗拱、出檐的逻辑；石材有砌缝层级 | 悬空构件、比例失真（门比人矮、檐比屋重） |
| 材质 | 旧木 / 石材 / 青瓦 / 布料 / 铜器 / 水面 六类清晰可辨，粗糙度差异明显 | 全场景一个灰材质、塑料感高光 |
| 光照 | 柔和、方向明确、有冷暖对比（暖灯 vs 冷月/晨雾） | 满屏泛光、全场景均匀亮、无方向 |
| 仙侠元素 | 克制：灯火、雾、水面倒影、树影、少量旧符纸 | 悬浮符文、荧光描边、夸张粒子、无意义发光装饰 |
| 色彩 | 低饱和自然色为主（青黛/灰蓝/石色/木色），暖灯与月色作为点缀 | 高饱和霓虹色、统一滤镜糊掉层次 |
| 构图 | 前景遮挡 + 中景建筑 + 远景山体/塔楼/城墙，三层可读 | 空旷平原感、一眼望到底 |
| 界面 | 不出现战力榜、稀有度色块、满屏任务标记 | 网游式 HUD 视觉 |

**从参考图提取的四条硬性技术手段**（必须落到实现里）

| # | 手段 | 说明 | 工程落地 |
|---|---|---|---|
| 1 | **蓝调时刻 + 暖灯点缀** | 环境是冷蓝紫（天空、雾、月光、石面），暖橙只出现在灯火与窗内光。冷暖对比是氛围来源 | `environment_presets.early_night`（默认）；暖色面积 10%—20% |
| 2 | **湿石反射** | 雨后石街与水面把灯火拉成竖条倒影，是参考图最有辨识度的一笔 | 街道/广场粗糙度 0.42 + 启用 SSR；水面低粗糙度 + 法线滚动；正式阶段上平面反射 |
| 3 | **雾中第三层** | 远景山体剪影 + 山中多级塔，提供纵深与「世界很大」的感觉 | 7 座低模山体 + 2 座层叠塔（`_mountain` / `_pagoda`），靠雾与冷色退化 |
| 4 | **前景遮挡** | 柳枝、屋檐、灯架压住画面边缘，避免一览无余 | 城镇边缘树冠、桥头灯柱、商铺出檐已有；正式阶段补柳条与花枝 |

**与旧取色的差异记录**：第一版实现按「黄昏暖调」（sun 0.55 暖橙）出图，偏暖；按参考图复核后改为**蓝调时刻**（sun 0.18 残照 + moon 0.55 冷光）。`dusk` 预设保留备用（序章落灯观开场可用暖调）。

### 2.2 色彩分层（保证三层可读）

| 层次 | 饱和度 | 明度 | 手段 |
|---|---|---|---|
| 近景（0—8 m） | 基准 | 基准 | 材质细节、法线、污渍 |

| 远景（40 m+） | −30% | 抬高 | 雾/空气透视，剪影化 |

## 3. 光照与雾气标准

### 3.1 四时段参数表（推进剧情节点切换，不做实时钟）

| 时段 | 太阳 | 月亮 | 环境光 | 雾 | 曝光 | 情绪 |
|---|---|---|---|---|---|---|
| 黄昏 Dusk | `#E0A97A` energy 0.55，仰角 18° | `#BCD2FF` 0.45 | 0.62 | `#2C3644` 密度 0.008 | 1.15 | 温暖、将入夜 |
| 灯初亮 EarlyNight | 0.10 | 0.50 | 0.38 | 密度 0.012 | 1.20 | 灯火成为主光源 |
| 子时 LateNight | 0.02 | `#CFE0FF` 0.60 | 0.22 | 密度 0.014 | 1.25 | 冷月、静谧、悬疑 |
| 事后天明 Dawn | `#E8D8B8` 0.70，仰角 12° | 0.10 | 0.80 | `#C8CDD2` 密度 0.006 | 1.05 | 收束、清凉 |

当前工程只启用「黄昏」，其余三档为 M2 联动目标（`GameState.time_band` 字段已预留）。

### 3.2 硬规则

1. **一个主光方向**：太阳/月亮方向全场景一致；同一张图内不允许两个方向的高光。
2. **灯火是暖的、月色是冷的**：冷暖对比是氛围的主要来源，不要把所有光都调成同色温。
3. **动态光源预算 ≤ 30 盏**（灰盒实测值）。超出的灯笼用**自发光材质**表现；正式美术阶段改用烘焙（LightmapGI）。
4. **雾是分层工具**，不是滤镜：`fog_density` 0.006—0.014，远处结构保留 25% 以上可读性。
5. **辉光克制**：`glow_intensity ≤ 0.6`，只让灯火溢出，不让整幅画面发光。

## 4. 材质标准

| 材质类 | 反照率 | 粗糙度 | 金属度 | 纹理规格 | 细节要求 |
|---|---|---|---|---|---|
| 旧木 | `#6B4F35`→`#4F3A27` | 0.75—0.9 | 0 | 1024² tileable，albedo+normal+roughness | 木纹方向一致、有雨痕与磨损边 |
| 石材 | `#8C857A`/`#6F6A62` | 0.85—0.95 | 0 | 1024²，可四方连续 | 砌缝层级、局部青苔 |
| 青瓦 | `#46525E` | 0.6—0.75 | 0 | 1024²，带瓦垄法线 | 瓦垄方向沿坡向，檐口有瓦当 |
| 布料 | 红/金/绿 | 0.9—0.95 | 0 | 512² | 织纹、下垂褶皱（靠法线） |
| 铜器 | `#8A6A3A`—`#B98B4A` | 0.3—0.45 | 0.8—0.9 | 512² | 氧化斑、边缘磨亮 |
| 水面 | `#16333C` | 0.05—0.12 | 0.4 | 法线滚动 | 低粗糙度 + 法线动画；正式阶段加平面反射 |

**通用规则**：albedo 用 sRGB，normal/roughness/metallic 用线性；单材质单文件；同类材质**必须复用**，不新建近似材质（工程内已有 `scripts/world/mat_cache.gd` 做按色缓存）。

## 5. 模块化建筑规则（保证模块能真实连接）

### 5.1 网格与尺寸

| 项 | 数值 | 说明 |
|---|---|---|
| 基础网格 | **4 m** | 所有建筑沿 4 m 网格排布 |
| 墙体模块 | 4 × 4 × 0.35 m（宽×高×厚） | 高度以 0.35 m 台基 + 3.2 m 层高为单元 |
| 台基 | 高 0.35 m，外挑 0.35 m | 玩家可直接上，不做台阶动画 |
| 层高 | 3.2 m（单层）/ 3.2 + 2.8（两层） | 与人（1.7 m）比例可信 |
| 屋顶 | 举架比 1:3.5，出檐 0.8 m | 悬山/歇山两种模块 |
| 门洞 | 1.8 × 2.1 m | 与灰盒门尺寸一致，替换不需改交互范围 |
| 窗 | 1.0 × 0.8 m | 窗格 2×3 分格 |
| 栏杆 | 高 1.05 m，柱距 0.6 m | 桥、河沿、二层统一 |
| 桥拱 | 跨度 19 m / 拱高 2.1 m（千灯桥） | 分段 19 段，可用拱券模块拼 |

### 5.2 连接规则

1. 模块**原点在底面中心**，上表面为 y = 0 平面，便于堆叠。
2. 墙体端头预留 0.1 m 榫接余量，相邻模块直接贴合不穿模。
3. 屋脊、檐口、斗拱为**独立小模块**，允许按建筑尺寸重复实例。
4. 所有模块统一 `−Z = 正面`、`+Y = 上`，导入 Godot 前先归位。
5. 允许的尺寸缩放：仅整倍数（1× / 2× / 3×）；非整倍数缩放会导致纹理失真，禁止。

### 5.3 可复用场景组件清单（一次建、全城用）

| 组件 | 用途 | 复用范围 |
|---|---|---|

| `SM_Beam_Wood` / `SM_Bracket` | 梁、斗拱 | 建筑、戏台、牌楼 |
| `SM_Door_Panel` / `SM_Window_Lattice` | 门、窗 | 全部建筑 |
| `SM_Fence_Rail` | 木栏杆 | 桥、河沿、二层 |
| `SM_Bridge_Arch` / `SM_Bridge_Deck` / `SM_Bridge_Rail` | 拱券/桥面/栏板 | 千灯桥、后续石桥 |

## 6. LOD 与「哪些建筑需要做内部」

| 类型 | 处理 | 依据 |
|---|---|---|
| 玩家要进入的（灯籍小房、纸扎铺、戏台后台） | 需要门槛/内部结构，内部单独立一套简化墙 | 玩法：调查线索、与 NPC 对话 |
| 只在前景路过的沿街铺面 | **只做外壳**（正面 + 屋顶 + 招牌），背面省略 | 视线基本看不到背面 |
| 对岸剪影、远处塔楼/城墙 | 低模剪影 + 雾，不做法线细节 | 远景只读轮廓 |
| 街道地面 | 一块 tileable 石板 + 少量独立石块打破重复 | 避免全街拼砖导致 draw call 爆炸 |

LOD 策略：`LOD0`（近，带法线）→ `LOD1`（中，去法线、减半面数）→ `LOD2`（远，剪影）。Godot 用自动生成 LOD（Mesh → Generate LODs）即可，建筑模块不需要手工 LOD。

## 7. 命名与目录规范

```
res://assets/
├── source/         原始下载档（**只读，不覆盖**；保留 .blend 与原始 FBX/OBJ）
├── processed/      已处理可用档（.glb，导入 Godot 的唯一来源）
├── architecture/   SM_Building_A.glb, SM_Roof_Gable.glb …
├── props/          PROP_Tree.glb, PROP_Lantern_Round.glb …
├── materials/      M_Wood_Old.tres, M_Stone_Wall.tres …（共享材质，不嵌在模型里）
├── textures/       T_Wood_Old_Albedo.png / _Normal.png / _Rough.png
├── environment/    ENV_Sky_Dusk.tres, ENV_Moyi_Town.tres
└── reference/      概念参考图（**不参与构建**，仅存档）
```

> **原始档与处理档分离**（来自项目美术资料包 `开发文档/美术/美术.md` 的管线约定）：外部下载物一律先进 `source/`，在 Blender 里检查比例/原点/朝向/UV/法线/面数后，导出 `.glb` 到 `processed/` 再导入 Godot。**`processed/` 是唯一被场景引用的目录**，回滚或替换资产时不会污染原始档。

命名规则：`SM_` 结构模块 / `PROP_` 道具 / `M_` 材质 / `T_` 纹理 / `ENV_` 环境；中文名只出现在文档里，资源名一律 ASCII 拼音或英文，避免跨工具编码问题。

## 8. 资源格式与 Godot 导入注意事项

| 项 | 要求 |
|---|---|
| 格式 | **glTF 2.0 二进制 `.glb`**（Blender 直接导出；不用 .fbx/.obj，避免缩放与材质丢失） |
| 单位/朝向 | 1 Blender 单位 = 1 m；`−Z = 正面`、`+Y = 上`；导出时勾选 `+Y Up` |
| 变换 | 导出前 `Ctrl+A` 应用位移/旋转/缩放；场景中不留非 1.0 缩放 |
| 碰撞 | 在 Blender 里为可碰撞件建**简单碰撞代理**，命名 `<名称>-colonly`（Godot 导入即生成 `StaticBody3D`）；不要用高模做三角网碰撞 |
| 材质 | 单一材质球对应单一纹理集；导出保留材质，Godot 侧如需全局调参再抽成 `.tres` |
| 导入参数建议 | `Meshes → Ensure Tangents = 开`；`Meshes → Generate LODs = 开`（建筑）；`Animation → Import = 关`（建筑）/开（道具动画）；`Materials → Extract = 关` |
| 光照贴图 | 需要烘焙的静态件必须**UV2 展开**（Blender 用 Lightmap UV Pack 或 `UV → Smart UV Project` 后单独一通道） |
| 命名一致性 | 模型内部节点名与 `TownBuilder` 生成器替换点一一对应，便于「灰盒 → 正式资产」只换引用 |
| 验证 | 导入后在 Godot 里检查：缩放是否正确、法线是否翻转、材质是否丢失、碰撞体是否为 StaticBody3D |

## 9. 性能预算（1600×900 / RTX 3060 Laptop 实测基准）

| 指标 | 灰盒现状 | 正式阶段上限 | 手段 |

## 10. 来源与授权规则（零预算）

### 10.1 优先级

1. **原创建模**（Blender 自建）：仙侠特有件（斗拱、悬山顶、傩戏面具、牌楼）没有现成 CC0 资源，必须自建。
2. **CC0 资源库**：纹理、HDRI、通用道具优先采用。
3. **CC-BY**：可用，但必须在 `开发文档/资源台账.md` 登记署名（游戏内也需要一段署名说明）。
4. **禁止**：来源不明、仅「免费下载」未标授权、AI 生成后无法确认训练来源合规的资产直接入库。

### 10.2 候选来源（使用前逐条确认授权页）

| 来源 | 内容 | 授权 | 用途 |
|---|---|---|---|
| Poly Haven | HDRI、PBR 纹理、少量模型 | CC0 | 天空/环境光照、木石瓦纹理 |

## 11. 管线：Blender → Godot

1. **参考**：先在 `开发文档/reference/` 放构图与色彩参考（含 AI 概念图，标注「仅构图参考」）。
2. **白模**：Blender 按 §5 网格与模块尺寸搭白模，**先验证比例与连接**，不贴材质。
3. **导出验证**：导 `.glb` → 拖入 Godot → 与灰盒截图并排比对比例（门高 2.1 m、层高 3.2 m、人 1.7 m）。
4. **材质**：按 §4 参数做/取纹理；Blender 里做能反复使用的材质模板。
5. **碰撞**：加 `-colonly` 代理件，导出后确认 `StaticBody3D`。
6. **替换灰盒**：在 `scripts/world/town_builder.gd` 对应生成函数（`_building` / `_bridge` / `_lantern_row` / `_stall` / `_stage` / `_prop`）里改成实例化正式资产；**布局 JSON 不动**。
7. **回归**：跑无头冒烟 + `tests/test_data_integrity.tscn` + 三个视角截图（`--shot-view=town|bridge|player`），确认路线、交互距离、任务流程全部不受影响。
8. **记录**：`03_开发日志.md` 追加本次替换范围与性能数据。

## 12. 验收标准（每批资产替换后逐条打勾）

- [ ] 风格统一：与既有场景并排看不出材质/色彩习惯的断裂。
- [ ] 比例合理：门 2.1 m、层高 3.2 m、栏杆 1.05 m、人物 1.7 m，尺度关系正确。
- [ ] 材质可辨：木/石/瓦/布/铜/水 六类在不看说明的情况下能分辨。
- [ ] 路线可读：玩家进入场景 3 秒内能判断「往哪走、哪里是地标」。
- [ ] 碰撞正确：可走区域连续，无卡住点、无穿模，交互距离仍为 3.4 m 内可触发。
- [ ] 三个时段（黄昏/夜/天明）各出一张截图，光照方向与冷暖关系正确。
- [ ] 性能达标：三角面、draw call、帧时间在 §9 预算内（记录实测值）。
- [ ] 授权清晰：所有非原创资产在 `资源台账.md` 有登记，CC-BY 项已安排署名位置。
- [ ] 灰盒-正式资产替换后，任务/对白/线索/存档流程回归测试全绿。
