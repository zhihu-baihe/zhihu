## 2026-10-15 — M1 落地：Godot 工程骨架 + 墨邑古城·百花千灯会灰盒

### 决策

| 决策 | 理由 |
|---|---|
| 引擎定为 **Godot 4.7.2 stable（标准版）** | 用户 brief 指定 Godot 4.x；4.7.2 是当前主力稳定分支（4.6 已转部分支持、4.5 仅安全维护、4.4 已 EOL）。设计资料原写 UE5.8，本工程按用户 brief 改为 Godot，设计内容照搬（见 `04_设计文档到Godot映射.md`）。 |
| 不装 .NET 版 | 全程 GDScript，不引入 C# 工具链。 |
| 引擎装在 `E:/MyGame/tools/Godot/` | 用户允许在本目录下载安装；隔离在 tools/ 子目录，不污染系统环境，且不入库。 |
| 工程根 `E:/MyGame/yunque/`（纯 ASCII） | 规避中文路径在工具链/引擎里的编码风险（本机历史上出现过中文路径被 shim 传坏）。文档目录仍用中文。 |
| 地图用**数据驱动生成器**，不手写节点树 | 布局改动只改 `data/map_moyi.json`；M7 美术替换只需替换生成器里的几何函数，不动布局与任务数据。 |
| 内容数据全放 `data/*.json` | 对应设计文档「数据驱动、不要把内容写进单一关卡蓝图」的要求（TECH-01 / §45—46）。 |

### 产出

- 文档：`开发文档/README.md`、`01_开发路线图_ROADMAP.md`、`02_M1_墨邑花灯节_实现方案.md`、`04_设计文档到Godot映射.md`、`_参考源文档/`（MAP-01 地图设计 + 布局原型图）。

### 缺陷记录（本轮自检抓出，均已修复）

| # | 现象 | 根因 | 修复方式 |
|---|---|---|---|
| 1 | Godot 启动即报 `GameData` autoload 实例化失败 | `game_data.gd._validate()` 调用了不存在的 `_dialogue_nodes_for()` | 改名调用 `dialogue_nodes_for()` |
| 2 | **取得线索后 NPC 台词不变**（设计文档要求的核心行为失效） | `add_clue()` 只写 `clues` 字典，未写 `flags`；而对白条件、任务阶段、门禁全部读 `flags` | `add_clue()` 内同步 `flags[clue_id] = true`，线索即证据标记 |
| 3 | 校验器误报「add_item 引用未知物品 id/count」 | 校验器把 `{id,count}` 字典的**键**当成了物品 ID | 改为校验 `add_item.id` |
| 4 | 城镇生成中断、截图全黑 | 三处叠加：① 对 `StandardMaterial3D` 调用 `darkened()`（该方法属于 `Color`）② `for s in [-1.0,1.0]` 元素为 Variant，参与运算后 `:=` 无法推断（4.7 把该警告当错误）③ 一次编辑事故把 `var sign_text := ...` 与下一行并成一行 | 暗化改用颜色运算；循环变量显式标注 `for yy: float in [...]`；拆行 |

教训（写进协作约定）：**Godot 4.7 默认把 `INFERRED_DECLARATION` 当错误**，所有从 Dictionary/Variant 取值的地方都要显式标类型；批量编辑脚本后必须立刻跑一次无头冒烟，不能只看编辑是否成功。

| 决策 | 理由 |
