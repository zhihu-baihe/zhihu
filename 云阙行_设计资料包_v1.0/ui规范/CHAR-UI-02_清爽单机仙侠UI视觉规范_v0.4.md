# CHAR-UI-02｜清爽单机仙侠 UI 视觉规范 v0.4

**项目：**《云阙行：九灯照夜》  
**状态：** 高保真静态原型 / 待 UE5 UMG 实机验证  
**优先级：** 本文件替代 v0.3 中偏暗色、卡片堆叠、强稀有度色彩的 UI 视觉方向。旧版数值表与战斗规则不因此自动变更。

## 1. 设计目标

本版参考经典单机 RPG 的界面组织方式：状态、装备、技能/仙术、物品与任务使用清晰分开的页面；玩家打开菜单是为了看角色、理解装备、选技能，而不是查看一张充满战力数字、稀有度边框和发光模块的仪表盘。参考的是“信息分层、留白、简洁导航、叙事气质”，不是复制《仙剑奇侠传四》的原始 UI 资产或精确排版。

## 2. 与 v0.3 的主要区别

| 旧方向 | v0.4 方向 |
|---|---|
| 深蓝黑底、金边、发光卡片 | 温润纸白、青灰墨色、少量朱砂 |
| 每块信息都被独立边框包起来 | 主要靠留白与细线分区，仅关键区域用面板 |
| 战力总分、等级徽章、装备稀有度很抢眼 | 先看角色状态和叙事信息；不显示战力总分 |
| 高密度图标和标签 | 文本优先，图标只辅助识别，减少装饰 |
| 所有页面像运营后台 | 每页解决一个明确任务，场景/角色是视觉主体 |
| 霓虹高亮与大量渐变 | 平面色块、细线、轻微纸面层次 |

## 4. 排版与布局规则

- 目标基准：1920×1080（16:9）；左右安全边距 64 px；面板之间建议 24–32 px。
- 标题使用 Noto Serif CJK SC 或项目经授权的宋/仿宋字体；数值和交互正文使用 Noto Sans CJK SC 或同等可读字体。
- 角色大标题约 32–44 px；页面标题 24–28 px；正文 18–22 px；帮助信息不低于 16 px。
- 主导航使用文字标签与一条细色线表示当前页，不使用大型胶囊按钮。
- 面板边线约 1 px；圆角 0–3 px；不使用持续发光、厚重金框、动态稀有度描边。
- 颜色意义固定：朱砂用于生命/少量剧情强调；青黛用于当前操作；青蓝用于灵息；金色仅作器物小点缀。不能用颜色暗示未经设计的装备品质。
- 数值必须能追溯来源。详细页展示成长基础、装备加成、临时修正与最终值。
- 当前原型使用氛围立绘/场景图作比例参考；正式版本优先使用 UE5 角色实时模型或经人工审核的最终立绘。概念图不是实机截图。

## 5. 页面原型

### UI-01 角色状态
核心信息：角色名、定位、等级/经验、HP、MP、攻击、术力、防御、灵御、速度、命中评分、闪避评分、韧性、五灵亲和。人物立绘占左侧约 40%，右侧用两列平行属性显示。GUTS/战意仅在战斗或战斗相关详情显示，避免城镇菜单里混入战斗态资源。

### UI-02 详细属性
属性值分为成长基础、装备加成、临时修正、最终值。不要让最终值无法解释。当前命中评分与闪避评分暂不展示百分号，直至战斗命中公式单位确定。

### UI-03 装备界面
显示主武器、衣装、护符和两个饰品槽。中央是朴素装备列表，右侧用一小块器物图和简短文字展示装备效果、来源与换装前后数值。不存在随机强化失败或装备分数比较。

### UI-04 技能界面
按主动、被动、仙术分类；左侧可读列表，右侧展示效果、消耗和战术说明。技能树作为后续可选页面，不在首版强迫玩家理解大量节点。

### UI-05 物品界面
分类标签、清晰网格、数量与说明。常见物品采用克制的单色图标；关键剧情物件可用独特插画。

### UI-06 战斗 HUD
场景是主体。BOSS 名称、阶段和生命条位于上方；行动顺序轻量显示；队员 HP/MP 与命令菜单位于底边。预警提示采用短文本+图形，不能遮挡角色和关键场地。

### UI-07 NPC 对话与任务提示
背景场景保持可见；左上角只显示一条轻量主线提示，底部使用单层对白框，显示人物名字和不超过 2–3 行对白，选项保持简短。完整任务日志由按键主动打开，不常驻覆盖场景。

## 6. UE5 UMG 实现建议

| 页面 | 建议 Widget | 关键组件 |
|---|---|---|
| `WBP_CharacterStatus` | 角色状态 | 角色立绘/即时模型展示、等级、经验、HP/MP、8项战斗属性、五灵亲和 |
| `WBP_CharacterDetails` | 详细属性 | 成长基础、装备加成、临时修正、最终值与属性解释 |
| `WBP_Equipment` | 装备 | 角色模型、5个装备槽、已装备项、装备列表、效果文字、换装预览 |
| `WBP_Skills` | 技能 | 主动/被动/仙术分类、技能列表、消耗、倍率、战术说明、装备槽 |
| `WBP_Inventory` | 物品 | 分类页签、物品网格、数量、说明、使用/丢弃 |
| `WBP_BattleHUD` | 战斗HUD | 敌方名称/阶段/生命条、行动顺序、队员HP/MP、指令菜单、机制提示 |
| `WBP_DialogueQuest` | 对话与任务提示 | 地点标题、轻量主线提示、说话人名、对白、选项、继续提示 |

实现原则：使用一个主菜单根控件管理导航；用 WidgetSwitcher 切换状态/装备/技能/物品/队伍页面；通过 CommonUI（若项目采用）或统一输入路由实现键鼠/手柄导航；属性行、装备槽、技能行、背包格用可复用子控件；数据通过角色属性快照和 DataTable/数据资产提供，不允许 UI 每帧自行叠加属性。

## 7. 验收标准

1. 1920×1080、1600×900 与常见 16:9 屏幕无裁切；UI 缩放后正文保持可读。
2. 每个页面首屏只出现该页必需信息；没有与玩法无关的战力榜、随机强化、稀有度闪烁。
3. 装备预览不会提前修改存档；取消后数值恢复；确认后角色面板、战斗属性和存档一致。
4. 键盘方向键/鼠标与手柄焦点均能明确显示当前位置；焦点仅用底线/浅色底，不用大面积霓虹。
5. 对话 UI 不遮住人物脸、关键交互对象和字幕；BOSS HUD 不遮挡机制地标。
6. 色彩不作为唯一信息编码方式；HP/MP、选中状态和危险提示同时有文字或形状区分。
